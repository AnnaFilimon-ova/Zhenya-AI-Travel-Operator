# Женя: AI-оператор путешествий по России

Трек «О!дин запрос». Telegram-бот и мини-приложение: человек описывает поездку обычными словами, Женя подбирает жильё с учётом профиля (бюджет, питомцы, доступность, интересы, еда), показывает билеты, погоду и места рядом, собирает всё в корзину и оформляет заказ.

Бот: **[t.me/ZhenyaOperatorBot](https://t.me/ZhenyaOperatorBot)**. Напишите ему `/start` и опишите поездку, например: «Хочу в Казань на выходные, нас двое, бюджет до 4000 в ночь».

## Провайдеры и модели

| Что | Провайдер | Модель / источник |
|---|---|---|
| Агент (диалог, вызов инструментов) | Google Gemini | `gemini-3.5-flash-lite` |
| Голосовые сообщения | Groq | распознавание речи (ключ `GROQ_API_KEY`) |
| Жильё | OpenStreetMap | каталог в PostgreSQL, импорт через Overpass |
| Места рядом | OpenStreetMap (Overpass) | запросы на лету |
| Погода | Open-Meteo | без ключа |
| Авиабилеты | Travelpayouts (Aviasales) | ключ `AVIA_API_KEY` |
| Поезда | собственная оценка по расстоянию | см. раздел про данные |
| Оплата | Telegram Payments | демо-режим или тест ЮKassa |

Ключи для жюри лежат в `secrets.env.age` (инструкция ниже).

## Честно про данные

Что настоящее, а что демонстрационное:

- **Жильё.** Названия, адреса, координаты и удобства взяты из OpenStreetMap. Рейтингов и реальных цен там нет, поэтому цена за ночь **оценочная** (по типу объекта, звёздам и городу). Бронирование демонстрационное.
- **Авиабилеты.** Цены из кэша Travelpayouts: это недавно найденные предложения, а не гарантированный тариф. Кнопка ведёт на поиск Aviasales за актуальной ценой.
- **Поезда.** Расписание и цены **смоделированы** по расстоянию между городами. Это не данные РЖД.
- **Оплата.** Деньги не списываются.
- Агент сам предупреждает об оценочных данных один раз за разговор.

## Как открыть и проверить бота

Самый простой путь: открыть [t.me/ZhenyaOperatorBot](https://t.me/ZhenyaOperatorBot) в Telegram. Команда держит бота запущенным на время проверки.

Если бот не отвечает, запустите проект сами (раздел ниже), создав своего бота у [@BotFather](https://t.me/BotFather) и подставив его токен в `BOT_TOKEN`.

## Запуск в Docker

Нужны Docker с Compose и [age](https://github.com/FiloSottile/age) для расшифровки ключей.

1. Клонируйте репозиторий и перейдите в его корень.
2. Получите `.env`. Если у вас есть закрытый ключ age организаторов:
   ```
   age -d -i key.txt -o .env secrets.env.age
   ```
   Без него скопируйте шаблон и заполните значения сами:
   ```
   cp .env.example .env
   ```
3. Запустите:
   ```
   docker compose up --build -d
   ```
   Поднимутся база PostgreSQL, веб-часть (API и мини-приложение, порт 8080) и бот. Схема базы применяется автоматически.
4. Загрузите каталог жилья (один раз, нужен интернет):
   ```
   docker compose exec app python -m scripts.import_osm Москва "Санкт-Петербург" Казань Сочи
   ```
5. Проверьте, что всё работает: `docker compose ps` (все сервисы `running`) и `http://localhost:8080/health`.
6. Откройте бота в Telegram и напишите `/start`.

Бот работает через long polling: для обычного диалога публичный адрес не нужен. Одному токену соответствует один запущенный бот. Токен из `secrets.env.age` принадлежит боту, который сейчас держит команда: чтобы запустить свою копию с ним, сначала сообщите нам, и мы остановим свою, либо создайте своего бота у @BotFather и подставьте его токен.

### Мини-приложение

Telegram открывает мини-приложения только по https. Чтобы кнопка меню работала, укажите в `WEBAPP_URL` публичный https-адрес, который ведёт на порт 8080 (например, через [ngrok](https://ngrok.com): `ngrok http 8080`), и перезапустите бота: `docker compose up -d --force-recreate bot`. Без `WEBAPP_URL` весь диалог в чате работает как обычно.

## Запуск без Docker

Нужны Python 3.11+ и PostgreSQL 16.

```
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r Backend/requirements.txt
cd Backend
uvicorn app.api.main:app --port 8080
python -m app.bot.main
```

Вторая команда запускается в отдельном терминале. `DATABASE_URL` в `.env` должен указывать на вашу базу, схема применяется при старте.

## Переменные окружения

Полный список с пояснениями в `.env.example`.

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота |
| `DATABASE_URL` | подключение к PostgreSQL (в Docker подставляется само) |
| `WEBAPP_URL` | публичный https-адрес мини-приложения |
| `GEMINI_API_KEY` | ключ Gemini |
| `GROQ_API_KEY` | ключ Groq для голоса |
| `AVIA_API_KEY` | токен Travelpayouts для авиабилетов |
| `HOTELS_API_KEY` | необязательно, внешний API отелей |
| `GEOAPIFY_API_KEY` | необязательно |
| `PAYMENT_PROVIDER_TOKEN` | необязательно: тестовый токен ЮKassa. Без него оплата имитируется |
| `DEV_USER_ID` | только для разработки в браузере. В боевой среде оставьте пустым |

Gemini доступен не из всех регионов. Если запросы к модели не проходят, запускайте проект с сервера или через VPN в стране, где Gemini работает.

## Как это устроено

```
Telegram ─► Бот (aiogram) ─► Агент (Gemini + инструменты) ─► Жильё, места, погода, билеты
    │            │
    │            └─► Корзина / заказы ◄─ PaymentProvider (демо / ЮKassa)
    ▼                                              │
Мини-приложение ─► API (FastAPI, подпись Telegram) ─► PostgreSQL
```

| Слой | Где лежит |
|---|---|
| Бот | `Backend/app/bot/` |
| Агент и инструменты | `Backend/app/agent/` |
| Провайдеры данных (жильё, места, погода, транспорт, оплата) | `Backend/app/providers/` |
| Каталог жилья | `Backend/app/catalog.py`, `Backend/scripts/import_osm.py` |
| Корзина, билеты, заказы | `Backend/app/cart.py`, `Backend/app/tickets.py`, `Backend/app/payments.py` |
| API мини-приложения | `Backend/app/api/` |
| Мини-приложение (русский и английский) | `Backend/webapp/` |

Источники данных подключены через провайдеры с единым интерфейсом. Чтобы заменить OSM-каталог на реальный API отелей, достаточно реализовать провайдер с теми же полями ответа: агент и интерфейс не меняются. Так же заменяются транспорт и оплата.

## Безопасность

- Мини-приложение и API проверяют подпись Telegram (`initData`) на каждом запросе. Заказ создаётся только после подтверждённого платежа, сумма проверяется на сервере.
- Агент работает только в рамках путешествий. Тексты из внешних источников и сообщения пользователей считаются данными, а не командами. Аргументы инструментов проверяются перед вызовом.
- Секреты не хранятся в репозитории: открытого `.env` нет, ключи передаются в `secrets.env.age`. Docker-образ собирается без `.env` и запускается не от root.

## Ограничения

- Нет реальных цен и рейтингов на жильё, поезда смоделированы. Данные о питомцах и доступности есть только у части мест, остальное помечено как неподтверждённое.
- Каталог покрывает несколько городов, обновляется вручную.
- Память диалога хранится в процессе бота: для нескольких экземпляров её нужно вынести в общее хранилище.
- Миграции базы идут через идемпотентный `schema.sql`, без Alembic.
- Бронирование и оплата демонстрационные.
